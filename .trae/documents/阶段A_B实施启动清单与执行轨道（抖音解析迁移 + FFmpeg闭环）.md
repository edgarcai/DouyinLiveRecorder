# 阶段A/B实施启动清单与执行轨道（抖音解析迁移 + FFmpeg闭环）

## 启动总纲
- 目标：在不破坏现有接口与数据结构的前提下，完成抖音解析真实迁移（阶段A）与 FFmpeg 执行闭环（阶段B），并建立可观测与验收的质量门禁。

- 指标：IPC 端到端 `p95 < 50ms`、解析耗时均值缩短 ≥30%、录制启动 `p95 < 1.5s`、长跑内存降低 ≥20%、QPS 达标（Fetch/Plan ≥100、Start/Stop ≥40）。

## 阶段A：抖音解析真实迁移（D1–D12）
### A1 架构对齐（D1–D2）
- 梳理 Python 抖音解析流程：入口调用、HTTP 细节（UA/Cookie/Headers/HTTP2）、页面/接口解析分层、x-bogus 签名调用点、质量映射与回退策略、异常分类。
- 输出《抖音解析器设计说明》：
  - 接口签名与状态机（RoomInfo 字段到平台字段映射表）。
  - 错误分类（风控/限频/Cookie失效/网络抖动）与降级返回路径。
  - 签名策略（goja 优先、Node 子进程回退、版本缓存与热更新）。

### A2 JSEngine 接入（D3–D5）
- 技术方案：
  - 使用 goja 加载 `assets/js/x-bogus.js`，设置执行超时与上下文；失败回退到 Node 子进程（命令行或长期驻进程模式）。
  - 结果缓存：按输入参数哈希缓存短期结果，记录签名版本号（便于回归与比对）。
- 验证：
  - 单测：脚本加载、执行正确性、超时/异常回退、缓存命中与失效策略。
  - 压力：快速多次调用签名（≥1k 次）验证 p95 与错误率。

### A3 HTTP 客户端策略（D6–D7）
- 实现要点：
  - 统一 `http.Client`（HTTP/2、连接池、代理、重试、超时分级、Header/UA 轮换）。
  - Cookie/Authorization 从 `ConfigService/AuthService` 读取；支持动态刷新。
  - 错误码映射（风控/限频/鉴权失败）到可降级行为（回退质量或备用源）。
- 验证：
  - 单测：超时/重试与代理启用、鉴权缺失与失败的分支覆盖。
  - 采样：记录 `p50/p95/p99`（请求阶段）与错误率。

### A4 解析实现与联调（D8–D12）
- 实现 `DouyinSpider.FetchRoomInfo(url)`：
  - 元数据：标题/主播/状态/质量列表。
  - 源解析：m3u8/flv 多质量源、协议白名单与优先策略、回退链路（质量降级→协议切换）。
  - 风控识别：验证码/限频/签名失效→降级与告警。
- 联调：
  - 打通 `SpiderService/Pipeline`；以黄金用例（固定房间与期望质量）进行 A/B 比对（旧版 Python vs 新版 Go）。
  - 验收：字段一致性（零差异）+ 性能采样达标（解析链路均值缩短 ≥30%、RPC `p95 < 50ms`）。

## 阶段B：FFmpeg 执行闭环（D16–D22）
### B1 参数矩阵与资源守护（D16–D17）
- 参数矩阵：分段（`-f segment/-segment_time`）、格式（TS/MP4/MKV/FLV）、音频模式（M4A/MP3）、代理/协议白名单、Headers 注入；根据平台/质量选择最稳组合。
- 资源守护：磁盘空间阈值预检与预警、进程权限与句柄上限、停止流程确保资源释放。
- 验证：参数组合单测与空间不足分支覆盖。

### B2 运行器实现与事件（D18–D20）
- 运行器：进程启动/停止、stdout/stderr 解析与分段事件识别；结构化日志字段（task_id/platform/quality/bitrate/segment_seq/error_code）。
- 事件：Wails 构建标签下推送 `record_started/segment_completed/record_stopped/error`；前端订阅与展示（主界面事件流）。
- 验证：
  - 启停一致性：连续启停 100 次无句柄泄漏与残留子进程。
  - 分段完整性：分段文件时间误差 ≤1s，丢段率 <0.1%。

### B3 错误监控与重试（D21–D22）
- 错误分类：网络（超时/断连）、协议（流不可用）、写盘（权限/空间不足）。
- 重试策略：指数退避（1s→30s）、最大重试 5 次、熔断与告警（标记任务失败/回退提示）。
- 验证：短断网/抖动模拟，自动恢复比例 ≥95%。
